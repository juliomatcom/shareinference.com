# Data model

Postgres 17, knex migrations in `apps/api/src/adapters/postgres/migrations/`. Ids are UUIDs unless noted. All timestamps `timestamptz`.

| Table            | Columns (key ones)                                                                                                                                                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `users`          | `id`, `github_id` (unique), `github_login`, `github_created_at`, `avatar_url`, `display_name` (unique, case-insensitive), `device_label`, `suspended_at`, `rate_limit_override` (jsonb, null), `created_at`                                                                                |
| `sessions`       | `token_hash` (pk), `user_id`, `expires_at`, `created_at`                                                                                                                                                                                                                                   |
| `api_keys`       | `id`, `user_id`, `name`, `prefix`, `key_hash` (unique), `created_at`, `last_used_at`, `revoked_at`                                                                                                                                                                                         |
| `models`         | `id` (text pk, public id), `webllm_id` (unique), `context_window`, `vram_mb`, `price_multiplier` (int, default 1), `enabled`                                                                                                                                                               |
| `workers`        | `id`, `user_id`, `device_key`, `gpu` (jsonb), `last_model`, `last_seen_at`, `created_at`; unique (`user_id`, `device_key`)                                                                                                                                                                 |
| `jobs`           | `id`, `consumer_id`, `provider_id`, `worker_id`, `model_id`, `lane`, `source` (`api` default / `playground`), `status` (queued/running/succeeded/failed/cancelled), `prompt_tokens`, `completion_tokens`, `credits`, `decode_tps`, `error_code`, `created_at`, `started_at`, `finished_at` |
| `ledger_entries` | `id` (bigserial), `user_id`, `amount` (bigint, signed), `kind` (grant/spend/earn/adjust), `job_id`, `note`, `idempotency_key` (unique), `created_at`                                                                                                                                       |
| `balances`       | `user_id` (pk), `balance` (bigint), `updated_at`                                                                                                                                                                                                                                           |
| `votes`          | pk (`voter_id`, `provider_id`), `value` (smallint ±1), `job_id`, `created_at`, `updated_at`                                                                                                                                                                                                |

## Invariants

- No prompt or completion text is stored anywhere.
- A `votes` row is (voter, provider) with the job that last set it; it needs a succeeded job of the voter served by that provider.
- `balances.balance` = sum of that user's `ledger_entries.amount` (checked by test and by CLI `pnpm ledger:check`).
- A `balances` row is created with the user (balance 0, plus grant if configured).
- Display names: 3–32 chars `[A-Za-z0-9_-]`; default = GitHub login; may not equal another user's GitHub login or a reserved name ([api.md](api.md)); a GitHub login outranks someone else's display name equal to it.
- Device label: optional, ≤ 40 chars, printable.
- Jobs: a row is created `queued` at admission, `running` when a worker is picked (again after a requeue, so `provider_id` / `worker_id` are the last worker tried), and ends `succeeded` (tokens, credits, `decode_tps`, `finished_at`), `failed` (`error_code`: `provider_failed`, `network_busy`, `no_providers`, `settle_failed`, `api_restart`) or `cancelled` (`client_cancelled`; a consumer cancel after delivered output that the worker confirmed ends `succeeded` instead). `provider_id` is null until dispatched. An ended job is never changed again; settlement and its two ledger entries commit in one transaction. At startup the api marks leftover queued/running rows `failed` / `api_restart`. Indexes: (`consumer_id`, `created_at` desc) for history, (`provider_id`, `status`) for provider totals, partial (`provider_id`, `finished_at` desc) where `status = 'succeeded'` for the leaderboard's latest-50 speed average. No prompt or completion text column exists.
- Enforced in the database: unique index on `lower(display_name)`, display-name format check, `ledger_entries.kind` and non-zero `amount` checks, and triggers that reject any UPDATE, DELETE or TRUNCATE on `ledger_entries` (append-only). Negative `github_id` marks a local test user (`pnpm users dev-session`).
- Live worker state (ready/busy, current job) is in memory only; `workers` is the durable identity for stats and the leaderboard. A `workers` row is upserted at `auth` (`gpu` and `last_model` are null until `ready`); `device_key` is 8-64 characters `[A-Za-z0-9_-]` (database check). At most 20 rows per user: when a new `device_key` would exceed that, the user's least recently seen row is deleted in the same transaction (`jobs.worker_id` is `ON DELETE SET NULL`, so the job keeps its provider).
