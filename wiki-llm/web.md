# web

Next.js (App Router) + Tailwind 4. No backend: `next.config` rewrites `/api/:path*` to `API_INTERNAL_URL` (the api on the compose network), so the session cookie is first-party. Design reference: `specs/design/landing.png` (dark theme, green accent). No `Content-Security-Policy` on the web yet: deferred post-MVP, see [conventions.md](conventions.md); the other security headers are in `next.config.ts`.

Public pages do not gate on `/api/me`; only the header uses it (Sign In vs user menu). Header bar (sticky at the top of the viewport): logo, then from `lg` up the core links and Share GPU: signed out How It Works, Model Catalog, Leaderboard, Docs (plus Sign In from `sm` up); signed in Dashboard, Leaderboard, Playground, Model Catalog. A burger menu sits at the top right on every width and holds the rest: signed in the name/avatar, How It Works, Docs, Settings; always View Repository; Sign out when signed in (Sign In below `sm` when signed out). Below `lg` the menu also carries the bar's links and Share GPU. Footer (every page): fair queue for free users, priority for credit holders, AGPL-3.0, repository, Privacy (`/docs/privacy`) and Terms (`/docs/terms`) links. The menu closes on Escape (focus returns to its button), on an outside click and on navigation.

- **Hero art and counter:** `Circuit` draws a pinned chip with routed trace bundles on each side (md and up; deterministic SVG, no `Math.random`); random traces carry a very fast light (~0.1–0.25 s per run) running toward the chip (`.circuit-pulse` in `globals.css`, off under reduced motion). The landing cards share rows (CSS subgrid), so both main buttons sit at the same height. `AnimatedNumber` counts the tokens-served figure up to each polled value (jumps under reduced motion).
- **Header while sharing:** the green Share GPU button becomes a blinking green dot plus the short status (Ready / Busy / Loading / Connecting / Reconnecting), linking to `/share`; in the burger menu (below `lg`) the item reads "Sharing: <status>". The dot's pulse stops under reduced motion.
- **Landing while sharing:** `HideWhileSharing` replaces the two main cards (earn / spend) with a one-line thank-you and a link to `/share` while the visitor is sharing; the hero stats and top providers stay.
- **Page art:** every page except `/` gets `PageArt` (root layout, `fixed`, md and up): thin trace bundles down both edges with 45° jogs, vias and pads, faded out toward the centre by a mask so content stays clear, with the same fast `.circuit-pulse` lights as the hero.
- **Live updates:** polling (D12), not SSE: the landing stats and leaderboard and `/models` re-fetch `/api/public/*` every 10 s while the tab is visible (and at once when it becomes visible); the api caches 5 s, so the freshest data is at most ~15 s old. A failed poll keeps the last good data.
- **Cookie note:** a small dismissible, non-blocking region (`CookieNote`, in the root layout above the footer, sticky at the viewport bottom) on a first visit: only strictly necessary cookies (`si_session`, `si_oauth_state`), no tracking or analytics, with a Privacy link and an OK button. Dismissal is kept in `localStorage` key `si_cookie_note` (reads and writes in try/catch); nothing renders until mounted. If the cookies ever change (analytics, etc.), this note and `docs/privacy.md` change with them.
- **Docs:** `/docs` pages are statically generated at build time from the repo's `docs/*.md` (the web Dockerfile copies `docs/` into the build stage; the runtime image needs no copy) with `react-markdown` + `remark-gfm`, raw HTML never rendered. Links in docs are written for the repo: sibling `*.md` become `/docs/<slug>`, other relative links (e.g. `../wiki-llm/api.md`) open the file on GitHub. Slug = file name, so a new `docs/x.md` needs only a rebuild. The file reads carry `turbopackIgnore` comments so the standalone trace stays free of the project and docs. `docs/privacy.md` and `docs/terms.md` are the human privacy and terms pages (drafts).
- Design reference mapping: the leaderboard "Credits earned" and "Model hosted" columns hide below `md`, "Device" below `sm`; tables scroll inside their card, never the page.

Gated pages show the sign-in panel (`SignInPanel`: GitHub button + "By signing in you agree to the Terms and Privacy policy" with links) when `/api/me` returns 401; header Sign In goes to `/signin` (same panel; a signed-in visitor is sent to `/dashboard`). The GitHub redirect only starts from that button.

## Playground page

- Own full-height page (`/playground`); the dashboard's API keys card links to it ("Try in Playground"). The body is the viewport height on this page only (`body:has([data-fill-viewport])` in `globals.css`): the chat list scrolls, the page never does, the footer is hidden and the cookie note sits below the composer instead of over it. Calls `POST /api/playground/chat/completions` with the session cookie (same-origin through the rewrite; no secret in the browser). The conversation lives only in component state: nothing is stored, reload or "New chat" clears it.
- `next.config.ts` sets `experimental.proxyTimeout: 190_000` so the rewrite proxy outlasts a job's 180 s total timeout (the api holds a queued request before its first byte; the proxy default is 30 s). SSE passes through the rewrite unbuffered.
- The "Thinking" switch (on by default; sends `enable_thinking`) has a tooltip and a `?` badge explaining it; the reasoning shows in a collapsible "Thinking" section on the reply. Send / Stop are normal-sized and vertically centred on the message box (the textarea is `block`, so no baseline gap under it).
- Model `<select>` from `GET /api/public/models`, only models with `workersOnline > 0`; none online: "No providers online right now" with a link to `/share`; a failed fetch with no data yet: "Could not load models. Retrying...". The list is polled every 10 s (like the other public pages), so both states clear by themselves.
- Streams with `stream: true`, `include_usage` and an explicit `max_tokens` (1024), parsing SSE lines across partial reads, `[DONE]` and `{"error"}` events. Send, a separate Stop button (AbortController cancels the job; clicks within 400 ms of Send are ignored), Enter sends (not during IME composition), Shift+Enter newline, textarea max 12 000 characters, "Thinking" toggle sends `enable_thinking`, `reasoning_content` goes in a collapsed "Thinking" disclosure. Text is rendered as plain text (`whitespace-pre-wrap`), never as markdown or HTML. A polite live region announces a reply only when it finishes.
- **Context meter:** shows `ceil(ASCII / 4) + non-ASCII code points` of what would be sent (the api's estimate, mirrored in `app/lib/playground.ts`) plus the reserved `max_tokens` against the model's `contextWindow`; amber from 80 %. When the next send would not fit (or exceed 256 messages) Send is disabled with "This conversation is too long for the model's memory (about N tokens, including the reply). Start a new chat to keep going." and an inline New chat button; on a fresh chat it says "This message is too long for the model." The api's context-length 400, the message-count 400 and a 413 map to the same texts. Other errors get friendly texts (429, 503, 403 `account_too_new`; for `no_providers` the api's own message, including the "only your own GPU" case).
- **Failures leave no trace:** an error before the first chunk (or a Stop before any output) removes the user message and the empty reply from the chat and puts the text back in the textarea; an error shown above the composer instead. A reply that failed after some output stays with its error and is never sent back as history.
- **Metrics** per reply, measured in the browser with `performance.now()`: prompt / completion / total tokens (from `usage`), first token (≈ queue + routing wait), duration, speed = (completion - 1) / (last chunk - first chunk) with at least 2 chunks, finish reason, credits. Credits are computed client-side: `(prompt × 1 + completion × 5) × priceMultiplier` (constants mirrored from [economy.md](economy.md) in `app/lib/api.ts`; the ledger is the truth) and shown as estimates. A stopped reply says it is partial and charged on the server for what was received; its tokens (prompt estimate, one token per received chunk) and credits are estimates and are counted in the chat total. A running total (replies, tokens, credits) is shown.
- Notes under the composer: credits are an estimate (exact amounts in the Ledger), the chat lives only in this tab, the context window limits conversation length, prompts are processed in a contributor's browser (link to `/docs/privacy`).
- Never shows the provider: no name, GPU, device, worker or provider-reported speed (the api does not send them; "served by" appears only in the dashboard history, D17). The dashboard history marks each request with an "API" or "Playground" badge (`source`).

## Share page

- Checks WebGPU on load (secure context, `navigator.gpu`, adapter `info.vendor`/`info.architecture`, `shader-f16`, `limits.maxBufferSize`); a clear message when unsupported (needs Chrome/Edge on localhost or HTTPS; `shader-f16` is required by the model).
- Model info from `GET /api/public/models` (one model in MVP): ~2.4 GB first download, cached afterwards.
- **Sharing outlives the page:** the worker and all sharing state live in `SharingProvider` (root layout; `useSharing()`), not in `/share`, so client-side navigation (all in-site links are `next/link`, no full reloads) never stops it. It ends only on Stop, a fatal error or expired session, signing out, or closing the tab. While sharing (and after a failure, until dismissed) `ShareBar` is a sticky bar above the footer on every page: status, credits earned, requests served (own numbers only), Details (-> `/share`) and Stop. WebGPU check and model info load when `/share` is first opened (`prepare()`).
- Start fetches `GET /api/public/config` (`apiPublicUrl`, D39: the api's address is learned at runtime), then starts a module Web Worker served as `apps/web/public/share-worker.js` (plain JS, no bundling). The worker imports WebLLM pinned from jsDelivr, loads the model with progress, runs one warm-up generation, then opens the WebSocket to `apiPublicUrl` (`/v1/worker`) per [worker-protocol.md](worker-protocol.md).
- Tokens: the worker asks the page (`postMessage`) for a worker token when it is about to connect, never earlier (60 s TTL vs. a model download), and again after every socket close. `deviceKey` is a random id the page keeps in `localStorage` (`si_device_key`) and passes in.
- Page <-> worker messages: page sends `start`, `token`, `token-failed`, `stop`; worker sends `status`, `progress`, `need-token`, `stats`, `fatal`.
- **ON / OFF control:** in the Status card (normal button size): off, a glowing green gradient "Turn ON" button with a power icon (greyed with the reason beside it until WebGPU, model info and the "I understand" box are ready); on, a "Sharing is ON" badge with a pulsing dot (pulse off under reduced motion). Next to it a red-outlined "Stop" button, its opposite, enabled only while sharing.
- Shows GPU info, load progress, status (loading / connecting / ready / busy / reconnecting / stopped) and live usage from `stats` (requests, prompt/completion tokens, last tokens/sec, credits earned). Never shows consumer identity or content.
- Contributor notice before Start: other people's prompts and replies pass through the browser while serving; the contributor must not inspect, store or misuse them (links to Terms and Privacy). Start stays disabled until the "I understand" checkbox is ticked; the acknowledgement is kept per account in `localStorage` key `si_share_ack:<user id>` (try/catch; unchecking clears it; the old browser-wide `si_share_ack` is adopted once by whoever signs in first). It is browser-local: a new browser or cleared storage asks again.
- Requests a screen Wake Lock while sharing and visible (asked again on `visibilitychange`); a failed request is ignored. Header nav has "Share GPU".
